2. Architecture Decision Records (ADRs) Summary

All 3 ADRs follow the mandatory COMP 205 template (Context, Prompt, Result, Rejected Suggestion, Verification, What I Learned):

  • ADR-001 (Clean Architecture): Decoupled UI and domain layers by encapsulating all Firebase operations inside the data layer. Rejected suggestion: Placing Firestore listeners directly in UI Riverpod controllers.
  • ADR-002 (KVKK & Compatibility Engine): Enforces strict isolation of sensitive roommate habits in private subcollections (users/{uid}/answers/). Rejected suggestion: Storing private answers in the root document with client-side field masking.
  • ADR-003 (Riverpod & GoRouter Guards): Implemented declarative authentication guards for routing transitions. Rejected suggestion: Using scattered imperative Navigator.push calls across UI buttons.

5. Security Rules Implementation Details

rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    function isAuthenticated() { return request.auth != null; }
    function isOwner(userId) { return isAuthenticated() && request.auth.uid == userId; }

    match /users/{userId} {
      allow read, write: if isOwner(userId);
      match /answers/{scenarioId} {
        allow read, write: if isOwner(userId); // KVKK/GDPR private
      }
    }
    match /publicProfiles/{userId} {
      allow read: if isAuthenticated();
      allow write: if isOwner(userId);
    }
    match /{document=**} {
      allow read, write: if false; // Catch-all denial
    }
  }
}
